# Model Collapse Recovery

Code for recursive synthetic-data training and weight-space recovery of language
models, with full-parameter and QLoRA fine-tuning.

## Setup

Use Python 3.12 on Linux with a CUDA GPU. Run commands from the repository root.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Configure Hugging Face access for gated models before running. Model weights
and datasets are downloaded separately.

## Methods

**Recursive training.** Generation 0 trains each model on real C4 text. Each
model then generates continuations from C4 prompt prefixes. The generated texts
are pooled across model families, and the next generation trains on this shared
pool starting from the preceding checkpoint. Stored text includes both the
prompt and continuation.

**Full-rank recovery.** Given a current checkpoint and a future checkpoint,
negate their weight update:

```text
theta_recovered = theta_current - alpha * (theta_future - theta_current)
```

**QLoRA recovery.** Apply the negative effective LoRA update to the preceding
merged checkpoint. The implementation scales the adapter's B matrices by
`-alpha` before merging, retaining the adapter's LoRA scaling factor.

**Evaluation.** Perplexity is the mean of per-example perplexities on a held-out
real-text split. Diversity metrics, including distinct-n, vocabulary size,
MTLD, and Yule's K, are computed after removing prompt prefixes.

## Training

```bash
# Preview generations 0 and 1 without running them.
python run_pipeline.py --config configs/fullrank.yaml --run-dir runs/fullrank42 --end-gen 1 --dry-run

# Run full-parameter or QLoRA training.
python run_pipeline.py --config configs/fullrank.yaml --run-dir runs/fullrank42
python run_pipeline.py --config configs/qlora.yaml --run-dir runs/qlora42
```

Configurations specify model families, data sizes, training, and generation
settings. `collapse.num_generations` is the last generation index: 9 runs
0–9. `--start-gen` and `--end-gen` select an inclusive range; starting above 0
requires the preceding checkpoints and synthetic pool.

`dataset.seed` controls data preparation and generation seeds;
`--training-seed` controls training and defaults to 42. Use a new run directory
when changing the configuration or seed. QLoRA resumes Trainer checkpoints;
full-rank training skips completed outputs and requires inspection of
interrupted outputs. Generation resumes completed shards.

Outputs are saved under the run directory:

```text
data/real/                       Real train/validation/test splits
data/synthetic_gen_<i>/<family>/  Generated text for each model
data/synthetic_gen_<i>/mixed/     Shared synthetic pool
models/<family>/gen_<i>/          Full-rank checkpoint
models/<family>/gen_<i>/adapter/  QLoRA adapter
models/<family>/gen_<i>/merged/   QLoRA merged checkpoint
results/                         Perplexity and diversity results
```

## Recovery

Recover generation 3 using the update learned at generation 4:

```bash
# Full-rank recovery.
python src/recover_fullrank.py --config configs/fullrank.yaml --base_dir runs/fullrank42 \
  --family llama --current_gen 3 --future_gen 4 --out_gen 9003 --alpha 1

# QLoRA recovery.
python src/recover_qlora.py --config configs/qlora.yaml --base_dir runs/qlora42 \
  --family llama --gen 4 --alpha 1 --output_dir runs/qlora42/recovered_llama_gen3_alpha1
```

Both methods write a new checkpoint and preserve the inputs.

## Evaluation

```bash
python src/evaluate.py --config configs/fullrank.yaml --base_dir runs/fullrank42 \
  --family llama --gen 3 --model_path runs/fullrank42/models/llama/gen_9003 \
  --output_file runs/fullrank42/results/recovered_llama_gen3_alpha1.json
```

For QLoRA, use `configs/qlora.yaml`, the corresponding run directory, and the
recovered checkpoint path. Recovered-model evaluation reports perplexity only
unless a corpus generated by that checkpoint is supplied through
`--diversity_data_path_override`.

For downstream tasks:

```bash
lm_eval --model hf --model_args pretrained=runs/fullrank42/models/llama/gen_9003,dtype=bfloat16 \
  --tasks hellaswag,arc_easy,arc_challenge,piqa,truthfulqa_mc2 --batch_size 4 \
  --output_path runs/fullrank42/results/downstream_recovered
```

## Small Tests

CPU tests construct tiny local models without downloading weights or data.
In a separate Python environment:

```bash
python -m pip install torch==2.10.0 --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements-test.txt
HF_HUB_OFFLINE=1 CUDA_VISIBLE_DEVICES="" python -m unittest discover -s tests -v
```

For a short GPU run with eight training examples and four continuations:

```bash
python run_pipeline.py --config configs/smoke.yaml --run-dir runs/smoke
python scripts/check_smoke.py runs/smoke
```

A Slurm wrapper is also available; activate the environment before submitting:

```bash
sbatch --gres=gpu:1 --cpus-per-task=4 --mem=32G --time=00:10:00 \
  slurm/run.sh --config configs/smoke.yaml --run-dir runs/smoke
```
